## 문제와 원하는 결과

대표님이 이체 후보를 「계좌끼리 옮긴 돈입니다」로 확인해도, 그 거래처를 아직 안 정했으면
`monthNumbersIn` · `daySplitIn` 이 「아직 안 정한 것」을 먼저 판정해 그 줄이 미정 금액 · 건수 · 일별 목록에 남았다.
확인한 이체는 미정이 아니라 「계좌끼리 옮긴 돈」으로 보여야 한다.

## 범위와 완료 조건

- 포함: 두 함수에서 확인된 이체(`xferOnIn`)를 미정(`isUnknownIn`)보다 먼저 판정.
- 제외: B안(첫 사용 질문에서 거래처 제외), 이체 후보 탐지 · 확인 · 저장 방식, 새 파일에 이체 답을 다시 묻는 규칙(`xferDataAnswers`).
- [x] 확인된 이체의 금액 · 건수만 `unknown` · `unknownN` 에서 빠지고 `unkPayees` · `unkRatio` 가 맞게 계산된다. 일반 미정 거래는 남는다.
- [x] 일별 목록에서 그 줄이 「계좌끼리 옮긴 돈」으로 나온다.
- [x] 「아닙니다」 · 「나중에 확인」은 기존대로 — 다른 분류가 없으면 미정.
- [x] 거래처를 정한 뒤 이체로 확인한 경우는 기존 결과 그대로.
- [x] 같은 거래처에 이체 · 일반 거래가 섞이면 일반 거래는 빠지지 않는다 (줄 단위).
- [x] 같은 저장 자료를 다시 열면 유지, 「모든 답을 확인 전으로」 하면 원래(미정)로 돌아간다.
- [x] 식당 예시(매출 68,436,321원 포함) 스냅샷이 그대로다.
- [x] 이체 확인 전후 매출 · 지출 · 순이익 · 실제 계좌 잔액이 같다.

## 구현 방법

- `app/src/core/compute.js` `monthNumbersIn`: `xferOnIn` 블록을 `isUnknownIn` 블록 앞으로 옮겼다. 적힌 금액 차액(`residual`)은 그대로 맨 앞.
- `app/src/core/result.js` `daySplitIn`: 같은 차례로 바꿨다. `dailyFlowIn` 은 두 경우 모두 건너뛰기만 해 차례가 결과를 안 바꾼다 — 그대로 둠.
- 이미 `due.js` 의 예측 · 보류 경로는 `xferOnIn` 을 먼저 본다 — 손대지 않음.
- 결과로 바뀌는 값: 확인된 이체 금액이 `unknown` · `uIn` · `uOut` 에서 빠지고 `keep` · `keepIn` · `keepOut` 의 「계좌끼리 옮긴 돈」으로 간다.
  그래서 순이익이 움직일 수 있는 폭(`lo` · `hi` · `blocked`)은 좁아진다. 매출 · 지출 · 순이익 · 잔액 · 예측 계산은 그대로다.
