# Codex 검수

Codex 가 코드 · 계획을 검수할 때의 규칙이다. 역할 분담의 배경은 [결정 0006](../decisions/0006-ai-roles.md).

## 언제

- **사용자가 요청할 때만** 한다. 자동 호출 · 자동 교차 검수 · 검수 뒤 자동 수정 루프는 없다.
- Claude Code 는 Codex 에 검수를 맡기지 않는다. 필요해 보이면 사용자에게 말할 뿐이다.

## 무엇을 근거로

- 요구사항(`specs/<작업>/spec.md`) · 확정된 계획(`plan.md`) · 코드 · 테스트 · 실제 실행 결과.
- 요청에 적힌 **경로 · 브랜치 · 커밋 또는 diff 범위**를 본다 ([workflow](workflow.md#검수를-요청할-때-범위를-적는다)). 범위가 없으면 먼저 묻는다.
- 상대 AI 의 대화 · 임시 메모(`.omc/` 등)를 찾아 읽지 않는다. 저장소에 커밋된 문서와 코드가 근거다.
- **계획 자체도 검토 대상이다.** 요구사항을 못 채우는 계획, 코드 사실과 틀린 계획이면 그렇게 말한다.

## 하지 않는 것

- 검수 요청만으로 파일을 고치지 않는다. 고치라는 요청이 따로 있을 때만 고친다.
- 문제가 없으면 없다고 한다. 개수를 채우려고 문제를 만들지 않는다.
- 검수 의견은 **승인이 아니다.** 채택 여부와 명세 상태는 사용자가 정한다.

## 결과 쓰는 법

발견마다 아래를 구분해 적는다.

| 구분        | 뜻                                                      |
| ----------- | ------------------------------------------------------- |
| 확인된 문제 | 재현했거나 코드로 분명히 보이는 것                      |
| 판단        | 설계 · 취향 · 우선순위에 대한 의견                      |
| 불확실      | 가능성은 있으나 확인하지 못한 것 — 확인하는 방법을 함께 |

각 발견에는 **위치**(파일:줄), **발생 조건**(어떤 입력 · 상태에서), **영향**(사용자 화면 · 계산 · 저장 자료 중 무엇이), **근거**(코드 · 테스트 · 명세의 어느 부분)를 단다.

```text
[확인된 문제] app/src/14-compute.js:172 — cutDay 가 있으면 …
  조건: …  영향: …  근거: tests/ledger.spec.mjs 를 … 로 바꾸면 실패
```

## 독립성에 대해

같은 저장소 문서를 읽으므로 두 AI 의 판단이 완전히 독립적이지는 않다. 특히 **Codex 가 자기가 쓴 계획을 검수하면** 같은 전제를 공유해 놓치는 것이 생길 수 있다.
독립적인 평가가 필요하면 사용자가 **새 Codex 대화**를 열고, 계획 문서 없이 요구사항(`spec.md`)과 코드 · diff 중심으로 검수를 요청한다.
