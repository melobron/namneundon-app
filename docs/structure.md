# 앱 파일 구조 (리팩토링 2단계 기준)

`app/` 폴더가 그대로 배포된다. 빌드 단계는 없다.

```
app/
├─ index.html            뼈대 + CSS·JS 불러오기 (205줄)
├─ css/app.css           화면 모양 전부
├─ src/                  JavaScript. 번호 순서대로 불러온다
├─ xlsx.full.min.js      엑셀 읽기 도구 (필요할 때만 불러옴)
├─ pdf.min.js · pdf.worker.min.js   PDF 읽기 도구 (필요할 때만)
├─ _headers              Cloudflare 캐시 규칙
├─ manifest.json · sw.js · icon-*.png   홈 화면 설치(PWA)
└─ robots.txt            검색 노출 차단
```

## core — 순수한 계산 (리팩토링 B-1, 진행 중)

`app/src/core/` 에는 **화면·저장소·바뀌는 전역(`UP`)에 닿지 않는 계산**만 둔다. 같은 입력이면 늘 같은 답이 나오고,
화면 없이 **Node 에서도 돈다** — 단위 테스트(`tests/core/`)와 테스트베드 VDI 계산에 쓴다.

| 파일                  | 하는 일                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `core/date.js`        | 날짜 → 날 번호 (`dayNum`, `dayMs`)                                                                   |
| `core/verify.js`      | 잔액 검산, 뒤바뀐 순서 바로잡기, 파일에 적힌 조회 기간 (옛 `05-verify.js`)                           |
| `core/parse-excel.js` | 은행 엑셀·CSV·HTML 표 → 거래 행 (머리글·열 찾기, 숫자·날짜 해석, 은행 이름) (옛 `03-parse-excel.js`) |
| `core/parse-pdf.js`   | PDF 글자 조각 → 표 → 거래 행, PDF 합계 확인 (옛 `04-parse-pdf.js`)                                   |

- core 파일은 `index.html` 에서 **맨 앞**에 불러온다.
- `npm run check` 가 core 규칙을 지킨다 (`tools/check-core.mjs`) — core 밖의 이름, 브라우저 기능, 지금 시각·난수, 최상위 값 바꾸기를 막는다.
- Node 에서 불러오기: `tests/core/load-core.mjs` 의 `loadCore()`.
- 어떤 함수가 순수한지: `npm run purity` (`tools/analyze-purity.mjs`, `--why 함수이름` 으로 이유).

## 지켜야 할 것

- **파일 순서가 곧 실행 순서다.** `index.html`의 `<script>` 순서를 바꾸지 않는다.
- 모든 함수와 변수는 아직 전역이다 (한 파일이었을 때와 같다). 모듈로 나누는 것은 3단계.
- 앞 파일이 불러오는 순간 뒤 파일의 이름을 쓰면 깨진다. 원래 한 파일일 때는 괜찮았던 일이다.
  `npm run check` (`tools/check-load-order.mjs`)가 이것을 찾는다. `npm test` 와 CI 에서 먼저 돈다.
