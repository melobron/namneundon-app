# 0002 · 빌드 단계 없이 `app/` 을 그대로 올린다

- 상태: **확정**
- 정한 때: 리팩토링 2단계(PR #2, 2026-09-23) 무렵. 2026-09-25 AGENTS.md 에 규칙으로 적혔다
- 정한 사람: 운영자

## 배경

앱은 원래 `index.html` 한 파일이었다. 리팩토링 2단계에서 CSS · JS 를 파일로 나눴지만,
번들러를 들이면 배포되는 파일과 저장소 파일이 달라지고 도구 · 설정이 늘어난다.

## 결정

- `app/` 폴더를 그대로 배포한다. 번들러 · 프레임워크 · 트랜스파일러를 들이지 않는다.
- JS 는 일반 `<script>` 로 차례대로 불러온다. 모듈로 바꾸는 일은 따로 정한다.
- 이 결정을 바꾸려면 사용자와 먼저 정한다 (명세 필요).

## 대안

- ES 모듈 + 번들러(Vite 등) — 전역 이름 문제가 사라지지만 빌드 · 배포 경로가 바뀌고 한 번에 바꿀 범위가 크다.
- ES 모듈을 빌드 없이 `<script type="module">` 로 — 가능하지만 전역 공유 방식을 전부 바꿔야 한다. 계산 핵심 분리(B-1) 때 다시 본다.

## 결과와 영향

- 저장소 = 운영. 테스트는 배포되는 파일을 그대로 연다.
- 모든 이름이 전역이라 불러오는 순서가 중요하다 → `tools/check-load-order.mjs` 로 지킨다.
- 앱 코드는 Node 에서 따로 돌리기 어렵다 ([architecture](../architecture/overview.md)).
