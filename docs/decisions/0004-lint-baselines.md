# 0004 · 오래된 코드의 검사는 기준선으로 묶는다

- 상태: **확정**
- 정한 때: 2026-09-25 (PR #8 코드 규칙 검사 도입)
- 정한 사람: 운영자

## 배경

오래된 앱 코드에 검사기를 들이자 이미 있는 경고 · 오류가 많았다. 한꺼번에 고치면 화면 · 계산이 바뀔 수 있다.

## 결정

- 도입 때의 개수를 **기준선**으로 묶고, 새로 늘면 실패하게 한다.
- 고쳐서 줄면 기준선을 그 수로 낮춘다. **기준선을 올리거나 검사를 끄지 않는다.**
- 현재 기준선 숫자는 설정 파일이 원본이다 ([quality](../development/quality.md#기준선)).

## 대안

- 검사를 도입하며 전부 고치기 — 동작 변경 위험.
- 오래된 코드를 검사에서 빼기 — 새 문제도 못 잡는다.

## 결과와 영향

- ESLint · html-validate 경고는 2026-09-25 에 0 이 되어 기준선이 사라졌다. Stylelint 와 앱 타입 오류가 남아 있다.

## 근거

- `package.json` 의 `lint:*` 스크립트, `tools/typecheck-app.mjs`, PR #8 · #10
