# 0006 · AI 역할 분담 — Codex 는 계획, Claude Code 는 구현

- 상태: **확정**
- 정한 때: 2026-09-25 — 사용자가 「AI Native 개발 체계 구축」 요청에서 정했다
- 정한 사람: 사용자(운영자)

## 배경

두 AI(Codex · Claude Code)를 함께 쓰면서 같은 사실을 보되, 서로의 대화나 임시 메모에 끌려가지 않고
사용자가 결정권을 쥐는 방식이 필요했다.

## 결정

| 누가        | 맡는 일                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| 사용자      | 제품 방향 · 중요한 설계 결정 · 계획 확정 · 검수 요청 여부 · 검수 의견 채택                             |
| Codex       | 큰 그림 · 요구사항 정리 · 아키텍처 제안 · 실행 계획. 구현은 사용자가 명시할 때만. 검수는 요청받을 때만 |
| Claude Code | 확정된 명세 · 계획으로 구현 · 테스트 · 구현 상태 기록. Codex 를 자동으로 부르지 않는다                 |

- 두 AI 는 **저장소의 문서(`AGENTS.md` · `docs/` · `specs/`)** 로만 사실을 나눈다. 대화 전문 · 임시 메모 · 내부 추론 · 상대의 답 요약 · 요청 안 한 검수 의견은 자동으로 나누지 않는다.
- 자동 호출 · 자동 교차 검수 · 자동 인계 · 자동 수정 루프를 만들지 않는다.
- 사용자의 그때그때 요청이 이 기본 역할보다 앞선다.

## 대안

- 한 AI 가 계획 · 구현 · 검수를 모두 — 자기 결과를 자기가 검수하게 된다.
- 도구끼리 자동으로 넘기고 검수하는 연결(플러그인 · 스크립트) — 사용자가 흐름을 놓치고, 대화가 섞인다.

## 결과와 영향

- 절차: [workflow](../development/workflow.md) · 검수: [codex-review](../development/codex-review.md)
- 공유 문서만으로 두 AI 의 **완전한 독립성은 보장되지 않는다.** 같은 문서를 읽고, 특히 Codex 가 자기 계획을 검수하면 같은 전제를 공유한다. 독립적인 평가가 필요하면 새 Codex 대화에서 요구사항과 코드 중심으로 검수를 요청한다.
