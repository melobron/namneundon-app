# 124차 — 결과 화면 AI 질문 시험

2026-10-16 사용자의 직접 구현 요청으로 작성했다. 별도 프로젝트 설계 문서는 직접 열람하지 않았으며,
이번 요청에 붙인 명세와 대화에서 확정한 범위를 근거로 했다. 앱은 정적 파일 그대로이며 `chat/`만 별도 Worker다.
push·PR·병합·배포·wrangler 실행·D1 생성은 이 작업에 포함하지 않는다.

## 경계와 저장

- 기본 숨김. 국외 이전 조건 확인 전에는 **합성 자료 시험자만** 쓴다.
  - 앱: `?aikey=<키>`로 들어오면 키를 이 브라우저(`fc.ai.tester`)에 저장하고 표시를 켠 뒤 `history.replaceState`로 주소창에서 키를 바로 지운다.
    키가 없으면 진입 아이콘을 그리지 않는다. `?ai=1`만으로는 켜지지 않는다. `?ai=0`은 표시와 키를 함께 지운다.
  - 서버: `POST /api/chat`·`DELETE /api/chat/*`는 헤더 `X-Namneundon-Tester`가 비밀값 `TESTER_KEY`와 같을 때만 처리한다.
    없거나 다르면 본문을 읽기 전에 403 — AI 호출·사용량 기록·저장 없음. 두 값을 SHA-256 해시로 바꿔 끝까지 비교한다(상수 시간).
    `TESTER_KEY`가 설정되지 않았으면 모든 질문·삭제가 403이다.
  - 키는 요청 헤더로만 보낸다. 전송 요약·화면·로그·스크린샷에 넣지 않는다.
    키는 **영문 소문자·숫자만**(1~256자) 쓴다(예: `openssl rand -hex 32`). 앱은 다른 형식을 저장·표시하지 않고, 서버는 형식이 다른 비밀값·헤더를 403으로 막는다.
- 진입점은 **결과 화면 오른쪽 아래 동그란 아이콘** 하나다. 앱에 있는 남는돈 마크(`BRAND_MARK`) + 작은 「AI」 표시, 접근성 이름 「AI에게 결과 묻기」.
  휴대폰(520px 이하) 48px, PC 56px. 화면 끝에서 16px + 안전 영역(`env(safe-area-inset-*)`). 다른 화면에서는 결과와 함께 감춰진다.
  - 아이콘이 결과를 가리지 않도록 결과 화면 맨 아래에 아이콘 높이 + 여백만큼(휴대폰 80px, PC 88px + 안전 영역) 비운다.
    결과 영역 높이는 제한하지 않는다 — 스크롤은 지금처럼 창(window)이 한다.
  - 시험 키가 없으면 아이콘·여백·질문 창 요소가 하나도 없다. main(`3b2c4a4`)과 스크롤 자리·높이·여백·390 화면이 같다.
  - 가림 기준: 모든 금액·[항목 바꾸기]를 아이콘에 가리지 않는 위치로 스크롤해 보고 누를 수 있어야 하고, 맨 아래까지 내렸을 때 마지막 줄이 아이콘에 가리면 안 된다.
- 질문 창은 **채팅 화면**이다. 휴대폰은 전체 화면, PC 는 오른쪽 아래에서 올라오는 380px 창.
  - 맨 위: 「남는돈 AI」 + 「시험 중」 + 더보기(⋯) + 닫기(×). 「대화 삭제」·삭제 안내·문의 안내는 더보기 안의 작은 보조 메뉴다.
  - 닫기·휴대폰 뒤로 가기(popstate)·Esc 가 질문 창을 닫는다. 닫기는 전송·대화 삭제를 하지 않는다. 질문 창이 열려 있는 동안 아이콘은 감춘다.
  - 가운데 말풍선: 첫 봇 말풍선 「보고 계신 결과에서 궁금한 점을 물어보세요.」와 예시 칩 3개(「이번 달 결과를 설명해 줘」·「차액과 통장 잔액은 왜 달라?」·「아직 안 정한 돈은 뭐야?」).
    칩은 입력 칸만 채우고 자동으로 보내지 않는다. 줄을 바꿔 감싸며 가로로 넘기지 않는다.
  - 대표님 질문은 오른쪽, AI 답은 왼쪽 말풍선. 답은 글자로만 넣는다(HTML 실행 없음). 한도 초과·시험 키 거절·오류도 봇 말풍선이며 「결과 화면은 계속 사용할 수 있습니다」를 붙인다.
  - 맨 아래 고정: 입력 칸 + 보내기 아이콘 단추(접근성 이름 「보내기」), 그 아래 작은 글씨 「AI 답변은 틀릴 수 있습니다. 질문에 계좌번호·연락처 같은 개인정보는 적지 마세요.」
- **보내기를 누르면 바로 보낸다.** 첫 전송을 막던 동의 카드는 없앴다. 입력 칸 바로 위에 늘 보이는 작은 글 두 줄:
  - 1줄 「질문과 선택·비교 기간의 업종·금액 요약을 Cloudflare로 보내 답변을 만듭니다. 운영자 확인을 켜지 않으면 질문은 서버에 남지 않습니다. · 자세히」
  - 2줄 「앞선 대화는 답변에 반영되지 않습니다.」 그 아래 주의 한 줄(「AI 답변은 틀릴 수 있습니다…」)은 그대로다.
  - 「자세히」 펼침 상자: 남는돈이 자동으로 붙이는 것(보낼 내용 표) / 대표님이 직접 적는 것(질문 칸 글은 그대로 전송, 계좌번호·이름·연락처 금지) /
    받는 곳 Cloudflare(서버·Workers AI)·목적 답변 생성 / 개인정보 처리방침.
    **TODO**: 사이트(namneundon.com) 처리방침은 접힌 상자라 바로 가는 주소가 없고 AI 전송을 다루지 않는다. 지금은 「개인정보 처리방침: 준비 중」으로 둔다(`CHAT_PRIVACY_URL`).
  - 답변마다 붙던 「운영자 열람용 대화 기록을 저장하지 않았습니다」는 없앴다(켠 질문에만 「운영자 확인용으로 저장했습니다」).
- **운영자 확인용 저장은 ⋯ 메뉴의 선택 켜기**다. 「운영자 확인용 저장: 꺼짐」(기본) → 누르면 설명과 [켜기]/[취소].
  - 설명: 「[선택] 서비스 개선을 위해 앞으로 보내는 질문·답변과 업종을 남는돈 운영자가 확인하도록 저장합니다. 저장 항목: 질문, 답변, 업종, 작성 시각, 대화 번호, 삭제 키 확인값.
    질문에 직접 적은 금액·이름도 함께 저장될 수 있습니다. 대표님이 지우시거나 14일이 지나면 지웁니다. 데이터베이스의 되돌리기 기능 때문에 지운 뒤 7일 동안은
    되살릴 수 있는 상태로 남고, 그 뒤에 사라집니다. 켜지 않아도 질문 기능은 그대로 쓰실 수 있고, 언제든 끌 수 있습니다. 켜기 전 대화는 저장하지 않습니다.」
  - 켠 동안만 `share=true`. 끄면(「켜짐 · 끄기」) 바로 다음 질문부터 저장하지 않는다. 켠 상태는 그 질문 창이 열려 있는 동안만 유지하고 저장하지 않는다(다시 열면 꺼짐).
  - 지우기 키(Authorization)·대화 번호(convId)는 **켠 질문과 「대화 삭제」 때만** 보낸다. 꺼진 질문은 본문 `{question, summary, share:false}`와 시험자 키 헤더뿐이며
    지우기 키를 만들지도 않는다. 서버도 꺼진 질문은 둘 없이 처리하고(convId 가 붙으면 400), 켠 질문은 둘 다 없으면 400.
  - 실명은 쓰지 않고 「남는돈 운영자」로만 쓴다.
- **추천 질문**: 주제 코드(고정) `운영판단·용어·잔액차이·기간비교·지출구성·지출비율·미분류·자료범위·업종비교·앞으로지출·기타`와 예상 질문 10개(`CHAT_TOPIC_CHIPS`).
  - 첫 화면 칩 최대 3개, 브라우저가 자료 상태로 고른다(`chatPickChips`): 아직 안 정한 돈 > 0 이면 미분류가 첫째, 비교할 이전 달(전체 기간 확보)이 있을 때만 기간비교,
    나머지는 용어·지출구성·잔액차이 순. 답변 아래 다음 질문 칩 최대 2개(방금 주제 제외, 같은 규칙). 업종비교·앞으로지출은 추천하지 않는다.
  - 칩은 입력 칸만 채운다(바로 보내지 않음). AI 가 추천 질문을 만들지 않는다.
- **주제 집계**: 질문을 보내 답을 받은 뒤 별도 요청 `POST /api/topic` 본문 `{topic, source}`만 보낸다(source: `chip`|`typed`).
  - 칩 문장을 그대로 보내면 칩 주제, 고쳤거나 직접 쓴 질문은 브라우저가 정해진 낱말 목록(`CHAT_TOPIC_WORDS`)으로 분류하고 맞는 낱말이 없으면 기타.
  - 지우기 키·convId·질문 글·요약·브라우저 식별값을 넣지 않는다. 시험자 키 헤더는 질문과 같은 출입 확인용으로 붙는다(키가 없거나 틀리면 403, 집계 없음).
  - 서버는 `topic_counts(day KST, topic, source, count)`에 +1. IP·헤더 값을 읽거나 저장하지 않는다. 고정 목록 밖 값·다른 칸은 400. 폐업·체납 같은 주제는 목록에 없다.
  - 시험 키 없는 일반 화면은 아무 요청도 보내지 않는다. 답을 받지 못한 질문(오류·한도·키 거절)은 세지 않는다.
- **답변 지침(SYSTEM)**: 운영판단은 평가 대신 확인 가능한 지난달 대비 변화만, 잔액차이는 일반 설명, 업종비교는 「남는돈에는 같은 업종 비교 자료가 아직 없어 비교해 드릴 수 없습니다」 + 대신 볼 것 한 가지,
  앞으로지출은 정할 수 없다고 말하고 보고 계신 달 숫자만, 자료범위는 전체 기간 확보 여부를 먼저 말한다. 요약에 숫자를 새로 더하지 않았다.
- 「보낼 내용 보기」는 실제로 보낼 요약 객체 하나를 한글 표로 보여준다. 값을 다시 계산하지 않고 글자로만 바꾼다.
  - 순서: 업종 → 선택한 달·전체 자료의 마지막 거래일·전체 기간 확보 여부 → 사업으로 번 돈·사업에 쓴 돈·차액 →
    매출·그 밖의 입금·아직 안 정한 돈 → 항목별 금액·매출 대비 비율, 업종별 재료·매입 비율 → 이전 달 요약(달 이름으로 접음).
  - 금액은 원 단위 쉼표, 비율은 소수 첫째 자리 %. 계산 못 한 비율(null)은 「확인 보류」. 표 아래 「비율은 보기 쉽게 반올림했습니다」.
  - 요약에 시작일은 없다. `dataEnd`는 「전체 자료의 마지막 거래일」로 쓴다(「8월 1~22일」로 만들지 않는다).
    `complete=false`는 「전체 기간 확보 미확인」이다(「진행 중」이 아니다).
- 보내기에서만 질문과 허용된 월 요약을 전송한다. 대화 이력은 전송하지 않는 단문 질문 단계다 — 말풍선이 이어져도 서버는 앞 질문을 모른다(입력 칸 위 2줄 안내).
- 원본 파일·거래 행·거래처 이름·매장 이름·계좌 정보·적요는 요약에 넣지 않는다.
- 사용자 지정 항목명에도 개인 이름이 있을 수 있어 `사용자 지정 항목`으로 합친다. 서버도 고정 항목명만 받는다.
- 비교는 직전 완결 달 최대 3개다. 거래일 범위가 모든 계좌에서 해당 월 첫날~말일을 포함해야 완결로 본다.
  거래가 없는 날과 파일 누락을 구분하지 못할 때는 미완결로 두는 보수적 기준이다. 연간 화면에서도 선택된 **달**을 명시한다.
- 질문 창을 열 때 요약을 고정하며 펼쳐 보는 값과 전송값이 같다. 매장·달 변경 시 다시 열도록 한다.
- `share=false`는 **운영자 열람용 대화·요약을 저장하지 않는다**는 뜻이다. 식별자 없는 일별 사용량은 계속 기록한다.
- 운영자 확인용 저장을 켠 질문만 질문·답변·업종·작성 시각·대화 번호와 삭제 키 해시를 D1에 저장한다. 답변에 들어간 금액도 저장된다.
- 예약 작업이 **1시간마다**(`15 * * * *`) 운영자 확인용 원문 **14일** 경과분과 주제 집계 **90일** 경과분을 지운다. 관리 목록에서는 이미 14일 지난 대화를 숨긴다.
  물리 삭제에는 예약 주기만큼 최대 1시간 지연이 있을 수 있다. 보관 전체는 아래 「보관 기간」.
- `fc.ai.enabled`(표시), `fc.ai.usage`(UTC 일자·횟수), `fc.ai.receipt`(대화 번호·삭제용 비밀 키),
  `fc.ai.tester`(시험자 키)를 새로 쓴다. 표시는 `fc.ai.enabled`와 `fc.ai.tester`가 함께 있어야 켜진다.
  기존 매장 저장 형식은 바꾸지 않는다. 대화 본문·요약·운영자 확인 켬 상태는 브라우저 저장소에 저장하지 않는다.
- 대화 번호만 알아서는 삭제할 수 없다. 브라우저의 256비트 삭제 키를 Authorization으로 보내고 서버에서는 해시로 대조한다.
  삭제는 해당 브라우저의 키에 연결된, 운영자 확인용으로 저장된 대화 전체다. 다른 기기 대화는 지우지 않는다.
  저장소를 지우면 키도 사라진다. 매장 「지우기」와 서버 대화 삭제의 차이는 챗봇 안에 안내한다.
- 로그에 본문을 출력하지 않고 observability·AI Gateway를 사용하지 않는다. Cloudflare 자체 처리·보관 정책은 별도 확인 대상이다.

| 개선 기록(날짜·주제·틀린 유형·메모) | D1 `improvement_notes` | 무기한(시각·업종 없음, 개인정보를 적지 않는 표, 대화와 연결하지 않음)         |
| 일별 사용량(뉴런)                   | D1 `usage`             | 그날까지(지난 날짜는 예약 작업이 지움)                                        |

- D1 되돌리기는 늘 켜져 있고 끌 수 없다. 무료 7일 · 유료 30일(<https://developers.cloudflare.com/d1/reference/time-travel/>).
- **체크리스트: Workers 유료 요금제로 바꾸면 되돌리기가 30일이 된다 → 앱 안내(14일 + 7일 문구)와 처리방침을 같은 날 고친다.**
- Logpush: 2026-10-16 계정에 구독·작업 없음 확인(사용자 확인).

## 처리 위치와 처리 위탁 (법률방 165차 확인 사항)

- AI 답변: Cloudflare, Inc.(Workers AI). 하위 처리자 CoreWeave(미국)·Nebius(영국). 앱 안내 「미국과 영국에 있는 Cloudflare로 전송」은 이 근거다.
- 대화 보관(운영자 확인을 켠 경우만): Cloudflare D1, 미국 관할(`--jurisdiction=us`로 만든다).
- Cloudflare DPA 6.4(2026-04-03): 4.3 하위 처리자 포괄 동의, 4.4 하위 처리자 변경 30일 전 공지·10일 안 이의.
  **이 계정이 DPA 에 동의했는지는 Cloudflare 설정 때 확인한다(아직 확인 안 함).**
- 입력 칸 위 안내: 「질문과 선택·비교 기간의 금액 요약(업종, 금액, 비율)이 미국과 영국에 있는 Cloudflare로 전송되어 답변을 만드는 데 쓰입니다.
  답변을 만든 뒤에는 남지 않습니다. 운영자 확인을 켜지 않으시면 질문은 남는돈 서버에도 남지 않습니다. · 자세히」,
  작은 글씨 「질문 칸에 가게 이름이나 성함을 적으시면 그대로 전송됩니다.」, 그 아래 「앞선 대화는 답변에 반영되지 않습니다.」

## 관리 화면(/admin, Cloudflare Access 그대로)

- 「주제 집계 내보내기(CSV)」 `/api/admin/topics.csv`: `week_start, topic, source, count`. UTF-8 BOM 을 붙여 엑셀에서 바로 열린다.
  - **내보내기 규칙**: 날짜 단위 서버 표를 한국 날짜 기준 **주 단위(월요일 시작)**로 묶는다(`week_start` = 그 주 월요일). 주·주제·출처별 합이 **3 미만이면 「3 미만」**으로만 쓴다.
  - 서버 표(`topic_counts`)는 날짜 단위 그대로 두고 90일이 지나면 예약 작업이 지운다.
- 「개선 기록」 입력: 주제(고정 목록)·틀린 유형(사실 틀림·숫자 틀림·말투·답 못함·기타)·메모(300자). 안내 「금액·가게 이름·성함·질문 원문 문장을 적지 마세요」.
  `improvement_notes(id, day, topic, kind, note)` 별도 표. 시각은 남기지 않고 날짜(한국, YYYY-MM-DD)만, 업종 칸 없음, 틀린 유형은 고정 목록만. 대화 번호와 연결하지 않고 자동 삭제하지 않는다. 같은 사이트·`X-Admin-Action: note` 일 때만 받는다.
- 「개선 기록 내보내기(CSV)」 `/api/admin/notes.csv`: `day, topic, kind, note`. `= + - @`로 시작하는 칸은 `'`를 붙여 수식으로 읽히지 않게 한다.
- 질문 원문 내보내기는 만들지 않는다. 저장된 질문은 관리 화면에서 14일 안의 것만 보고 지울 수 있다.

## 사용량과 오류

- 모델 기본값은 `TODO_MODEL`. 검증방이 후보의 한국어 품질·사용량을 재고 선택하기 전에는 503이다.
- 일별 한도 기본 8,000뉴런. D1 원자적 SQL로 호출 전 입력 바이트 수와 최대 출력량에 해당하는 양을 예약한다.
  모델 사용량 응답이 있으면 공식 단가로 정산하며, 사용량이 없거나 실패하면 예약량을 남긴다.
- 입력 바이트 기반 예약은 보수적 추정이다. 선택한 모델의 실제 토큰 수가 예약 상한을 넘지 않는지 실측해야 한다.
- UTC 자정(한국시간 오전 9시)에 일자가 바뀐다. 브라우저별 10회는 보조 장치이며 실패 요청도 횟수에 포함한다.
- CORS는 앱 origin 하나만 허용한다. CORS 자체는 인증이나 남용 방지가 아니다.
  공개 API를 직접 호출하면 전체 무료 한도를 소진할 수 있으므로 파일럿 공개 전에 남용 방어를 지원이 검토한다.
- 서버 장애·한도 초과가 앱 계산이나 저장을 바꾸지 않는다. AI 출력은 HTML로 실행하지 않고 글자로만 표시한다.
- 지시문(`SYSTEM`)은 차액을 「선택한 기간의 사업으로 번 돈 − 사업에 쓴 돈」으로 설명하고, 통장 잔액은 그 기간 전 잔액·대표님이 넣거나 가져간 돈·대출 등으로 다를 수 있다고 말하게 한다.
  계좌 간 이체 영향은 함께 보는 계좌에 따라 다르고 미정 거래도 차액에 영향을 준다. 요약에 시작·끝 잔액과 전체 입출금이 없으므로
  차이의 정확한 원인·금액은 확인할 수 없다고 말하며, 미분류 금액을 입출금으로 나누거나 날짜를 추정하지 않는다. 요약에 잔액은 넣지 않는다(잔액 칸이 있으면 400).

## Cloudflare에서 사람이 할 일 — 여기서는 실행하지 않음

1. 지원이 코드를 검토하고 운영자가 외부 시험 범위를 승인한다. 합성 자료부터 시험한다.
2. D1 생성(여기서는 만들지 않음): `wrangler d1 create namneundon-chat --jurisdiction=us`. ID를 `chat/wrangler.jsonc`에 넣고
   `chat/migrations/0001_init.sql`, `0002_topics_notes.sql`을 차례로 적용한다(기존 파일은 고치지 않고 새 파일로만 더한다).
   **`TESTER_KEY` 비밀값 넣기**: `wrangler secret put TESTER_KEY --config chat/wrangler.jsonc`로만 넣는다.
   값은 코드·설정 파일·대화·이슈에 적지 않는다. **영문 소문자·숫자만**(예: `openssl rand -hex 32`)으로 만든다 — 다른 글자가 섞이면 모든 질문이 403이다.
   넣지 않으면 모든 질문·삭제가 403이다. 시험자에게는 `?aikey=<키>` 주소를 안전한 경로로 한 번만 전달한다.
3. 모델 후보를 한국어 질문·미분류·불완전 기간·업종 비교·지시 무시 요청으로 실측. 선택 모델을 `CHAT_MODEL`에 넣는다.
4. `chat.namneundon.com`을 별도 Worker custom domain으로 연결한다. workers.dev·미리보기 주소는 계속 비활성화한다.
5. Cloudflare Access 앱을 `/admin` 및 `/api/admin/*`에 적용하고 운영자 이메일 하나만 허용한다.
   `ACCESS_TEAM`에는 팀 하위 도메인, `ACCESS_AUD`에는 해당 Access 앱 AUD를 넣는다.
   서버는 헤더 존재뿐 아니라 RSA 서명·발급자·대상·유효기간을 검증한다. 다른 주소로 우회되지 않는지도 시험한다.
6. 무료 플랜과 계정 전체의 다른 AI 사용량을 확인한다. 자동 유료 전환·AI Gateway 크레딧은 연결하지 않는다.
7. 입력·출력·오류 로그에 본문이 남지 않는지, 실제 모델 사용량과 D1 정산이 일치하는지 확인한다.
8. 예약 삭제·사용자 삭제·삭제 실패 재시도, 관리 화면 인증·만료·위조 토큰 거절을 실제 환경에서 확인한다.
9. 실제 처리업체·국가·보관·국외 이전 근거를 확인하고 개인정보 안내·그림을 웹사이트방과 맞춘다.
   기존 “거래내역이 밖으로 나가지 않음” 문구의 적용 범위와 AI 예외를 공개 전에 반영한다.
10. 서버 오류 시 기존 분석 유지, 360·390폭, 시험 키 없는 화면 무전송, 운영자 확인 꺼진 질문에 지우기 키·convId 없음을 외부 시험 환경에서 다시 확인한다.
11. 배포 작업은 `CHAT_DEPLOY_ENABLED=true`를 사람이 설정한 뒤 `workflow_dispatch`일 때만 열린다.
    D1·모델·Access 자리표시가 남으면 건너뛴다. **같은 workflow의 기존 앱 배포도 실행되므로** 실행 전 대상을 확인한다.
    D1 마이그레이션은 자동 실행하지 않는다. 운영자 배포 승인 전 이 설정을 켜지 않는다.
12. 배포 뒤 할 일: `wrangler tail`로 합성 질문·가짜 키 요청을 보내 tail 출력에 URL·헤더(Authorization·X-Namneundon-Tester)·IP가 어떻게 나오는지 실측한다.
    D1 되돌리기(Time Travel)로 되살린 뒤에는 그 사이 지운 대화가 다시 생기므로 지운 대화를 다시 지우는 절차를 정해 둔다.
