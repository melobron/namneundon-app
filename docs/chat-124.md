# 124차 — 결과 화면 AI 질문(베타)

2026-10-16 사용자의 직접 구현 요청으로 작성했다. 별도 프로젝트 설계 문서는 직접 열람하지 않았으며,
이번 요청에 붙인 명세와 대화에서 확정한 범위를 근거로 했다. 앱은 정적 파일 그대로이며 `chat/`만 별도 Worker다.
push·PR·병합·배포·wrangler 실행·D1 생성은 처음 작업에 포함하지 않았다. 124-5(2026-10-16 요한 승인)에서 시험 키를 걷어내고 공개로 바꿨다 — 아래 「공개 전환(124-5)」.

## 경계와 저장

- **공개(124-5)**: 결과 화면이면 누구에게나 아이콘을 보인다. 시험 키 검사는 앱·서버 모두 걷어냈다.
  - 앱: `?ai=0` 은 이 브라우저에서 끄기(`fc.ai.enabled`='0'), `?ai=1` 은 다시 켜기(그 값을 지움). 예전 시험 주소의 `?aikey=` 는 무시하고 `history.replaceState` 로 주소창에서만 지운다.
    예전에 저장된 `fc.ai.tester` 가 남아 있으면 지운다(이름은 `CHAT_KEYS.tester` 로 남겨 두되 새로 쓰지 않는다).
  - 서버: `POST /api/chat`·`DELETE /api/chat/*` 는 시험자 헤더 없이 처리한다. CORS 허용 헤더는 `Content-Type, Authorization` 둘이다.
    남용 방어는 하루 뉴런 한도(서버)·브라우저당 하루 10회(앱 보조)와 Cloudflare 요청 수 규칙(검증방 설정, 코드 밖)이다. 코드 안에 IP 별 제한은 없다.
- 진입점은 **결과 화면 오른쪽 아래 동그란 아이콘** 하나다. 앱에 있는 남는돈 마크(`BRAND_MARK`) + 작은 「AI」 표시, 접근성 이름 「AI에게 결과 묻기」.
  휴대폰(520px 이하) 48px, PC 56px. 화면 끝에서 16px + 안전 영역(`env(safe-area-inset-*)`). 다른 화면에서는 결과와 함께 감춰진다.
  - 아이콘이 결과를 가리지 않도록 결과 화면 맨 아래에 아이콘 높이 + 여백만큼(휴대폰 80px, PC 88px + 안전 영역) 비운다.
    결과 영역 높이는 제한하지 않는다 — 스크롤은 지금처럼 창(window)이 한다.
  - `?ai=0` 으로 끈 브라우저는 아이콘·여백·질문 창 요소가 하나도 없다(시험 기간에는 시험 키가 없을 때 그랬다 — main `3b2c4a4` 와 스크롤 자리·높이·여백·390 화면이 같았다).
  - 가림 기준: 모든 금액·[항목 바꾸기]를 아이콘에 가리지 않는 위치로 스크롤해 보고 누를 수 있어야 하고, 맨 아래까지 내렸을 때 마지막 줄이 아이콘에 가리면 안 된다.
- 질문 창은 **채팅 화면**이다. 휴대폰은 전체 화면, PC 는 오른쪽 아래에서 올라오는 380px 창.
  - 맨 위: 「남는돈 AI 비서」(124-6, 아이콘 접근성 이름 「남는돈 AI 비서에게 묻기」) + 「베타」 + 더보기(⋯) + 닫기(×). 「대화 삭제」·삭제 안내·문의 안내는 더보기 안의 작은 보조 메뉴다.
  - 닫기·휴대폰 뒤로 가기(popstate)·Esc 가 질문 창을 닫는다. 닫기는 전송·대화 삭제를 하지 않는다. 질문 창이 열려 있는 동안 아이콘은 감춘다.
  - 가운데 말풍선: 첫 봇 말풍선 「보고 계신 결과에서 궁금한 점을 물어보세요.」와 예시 칩 3개(「이번 달 결과를 설명해 줘」·「차액과 통장 잔액은 왜 달라?」·「아직 안 정한 돈은 뭐야?」).
    칩은 입력 칸만 채우고 자동으로 보내지 않는다. 줄을 바꿔 감싸며 가로로 넘기지 않는다.
  - 대표님 질문은 오른쪽, AI 답은 왼쪽 말풍선. 답은 글자로만 넣는다(HTML 실행 없음). 오류도 봇 말풍선이며 「결과 화면은 계속 사용할 수 있습니다」를 붙인다.
    하루 한도(서버 429·브라우저 10회)는 「오늘 AI 질문이 모두 마감됐습니다. 내일 오전 9시 이후 다시 물어봐 주세요.」(`CHAT_CLOSED`, 요금 낱말 없음).
  - 맨 아래 고정: 입력 칸 + 보내기 아이콘 단추(접근성 이름 「보내기」), 그 아래 작은 글씨 「AI 답변은 틀릴 수 있습니다. 질문에 계좌번호·연락처 같은 개인정보는 적지 마세요.」
- **보내기를 누르면 바로 보낸다.** 첫 전송을 막던 동의 카드는 없앴다. 입력 칸 바로 위에 늘 보이는 작은 글씨 한 문장(두 줄 안)과 ⓘ 단추:
  - 「질문과 금액 요약은 미국과 영국의 Cloudflare로 보내져 답변을 만드는 데에만 쓰이고 남지 않습니다. 질문에 적으신 이름도 그대로 전송됩니다.」(124-5 문구) + ⓘ(접근성 이름 「안내 자세히」, 32px).
    390 폭에서 두 줄, **360 폭에서는 세 줄**이다(10.5px, 자간 −0.03em, ⓘ 는 오른쪽 여백 안으로 6px). 글씨를 더 줄이지 않고 시험 기준을 360 만 세 줄로 두었다. 그 아래 주의 한 줄(「AI 답변은 틀릴 수 있습니다…」)은 그대로다.
  - ⓘ 펼침 상자(다시 누르면 닫힘): 「운영자 확인을 켜지 않으시면 질문은 남는돈 서버에도 남지 않습니다.」 / 「앞선 대화는 답변에 반영되지 않습니다.」 /
    남는돈이 자동으로 붙이는 것(보낼 내용 표) / 개인정보 처리방침. 예전 「· 자세히」 글자 단추는 없앴다.
    처리방침 링크는 `https://namneundon.com/privacy/#policy`(`CHAT_PRIVACY_URL`), 새 탭(`target=_blank`, `rel=noopener noreferrer`).
  - 답변마다 붙던 「운영자 열람용 대화 기록을 저장하지 않았습니다」는 없앴다(켠 질문에만 「운영자 확인용으로 저장했습니다」).
- **운영자 확인용 저장은 ⋯ 메뉴의 선택 켜기**다. 「운영자 확인용 저장: 꺼짐」(기본) → 누르면 설명과 [켜기]/[취소].
  - 설명: 「[선택] 서비스 개선을 위해 앞으로 보내는 질문·답변과 업종을 남는돈 운영자가 확인하도록 저장합니다. 저장 항목: 질문, 답변, 업종, 작성 시각, 대화 번호, 삭제 키 확인값.
    질문에 직접 적은 금액·이름도 함께 저장될 수 있습니다. 대표님이 지우시거나 14일이 지나면 지웁니다. 데이터베이스의 되돌리기 기능 때문에 지운 뒤 7일 동안은
    되살릴 수 있는 상태로 남고, 그 뒤에 사라집니다. 켜지 않아도 질문 기능은 그대로 쓰실 수 있고, 언제든 끌 수 있습니다. 켜기 전 대화는 저장하지 않습니다.」
  - 켠 동안만 `share=true`. 끄면(「켜짐 · 끄기」) 바로 다음 질문부터 저장하지 않는다. 켠 상태는 그 질문 창이 열려 있는 동안만 유지하고 저장하지 않는다(다시 열면 꺼짐).
  - 지우기 키(Authorization)·대화 번호(convId)는 **켠 질문과 「대화 삭제」 때만** 보낸다. 꺼진 질문은 본문 `{question, summary, share:false}`뿐이며
    지우기 키를 만들지도 않는다. 서버도 꺼진 질문은 둘 없이 처리하고(convId 가 붙으면 400), 켠 질문은 둘 다 없으면 400.
  - 실명은 쓰지 않고 「남는돈 운영자」로만 쓴다.
- **추천 질문**: 주제 코드(고정) `운영판단·용어·잔액차이·기간비교·지출구성·지출비율·미분류·자료범위·업종비교·앞으로지출·기타`와 예상 질문 10개(`CHAT_TOPIC_CHIPS`).
  - 첫 화면 칩 최대 5개(`chatFirstChips`, 124-3, 124-6 존댓말): 「번 돈은 느는데 왜 남는 게 적나요?」(운영판단) · 「인건비는 매출의 몇 %인가요?」(지출비율) ·
    「월세·공과금은 얼마 나갔나요?」(지출구성) · 「지난달보다 뭐가 달라졌나요?」(기간비교) · 「아직 안 정한 돈은 무엇인가요?」(미분류).
    아직 안 정한 돈 0원이면 미분류 대신 「어느 항목에 가장 많이 썼나요?」(지출구성), 비교할 이전 달(전체 기간 확보)이 없으면 기간비교 대신 「차액은 무슨 뜻인가요?」(용어),
    인건비(급여)·월세(임차료) 항목이 0원이면 그 칩은 빼고 남은 것만 둔다.
  - 답변 아래 다음 질문 칩 최대 2개는 그대로(`chatPickChips`): 방금 주제 제외, 미분류(있을 때)·기간비교(비교 달 있을 때)·용어·지출구성·잔액차이 순. 업종비교·앞으로지출은 추천하지 않는다.
  - 칩은 입력 칸만 채운다(바로 보내지 않음). AI 가 추천 질문을 만들지 않는다.
  - 124-6 에서 `CHAT_TOPIC_CHIPS` 10개 문장을 모두 존댓말로 바꿨다(요한 확정 일곱 개 + 다음 질문 칩에 나오는 「차액과 통장 잔액은 왜 다른가요?」 등 나머지도 말투를 맞춤).
    주제 분류·정해진 답은 낱말(「남는 게」「얼마 나갔」「달라졌」 등)로 알아보므로 새 존댓말·옛 반말·직접 친 질문을 같은 주제로 본다(시험: chat-worker 「질문 칸(존댓말)과 옛 반말 문구」).
- **주제 집계는 기본 꺼짐(124-5)** — 사이트 처리방침과 맞추려고 껐다. 코드는 남겨 두었다.
  - 앱 `CHAT_TOPIC_ON=false` 이면 `/api/topic` 요청을 보내지 않는다. 서버는 `TOPIC_COUNTS` 가 `on` 이 아니면 본문을 읽지 않고 저장 없이 204.
  - 켜면(둘 다 켜야 한다, 처리방침을 먼저 고친다): 답을 받은 뒤 별도 요청 `POST /api/topic` 본문 `{topic, source}`만 보낸다(source: `chip`|`typed`).
    칩 문장을 그대로 보내면 칩 주제, 고쳤거나 직접 쓴 질문은 브라우저가 정해진 낱말 목록(`CHAT_TOPIC_WORDS`, 서버 `TOPIC_WORDS` 와 같다)으로 분류하고 맞는 낱말이 없으면 기타.
    지우기 키·convId·질문 글·요약·브라우저 식별값을 넣지 않는다. 서버는 `topic_counts(day KST, topic, source, count)`에 +1. IP·헤더 값을 읽거나 저장하지 않는다.
    고정 목록 밖 값·다른 칸은 400. 답을 받지 못한 질문(오류·한도)은 세지 않는다.
- **숫자는 코드가 지킨다(124-5, `chat/src/answers.js`)** — 백테스트(2026-10-16)에서 지침만으로는 자릿수 밀림·지어낸 비율·없는 날짜가 남았다. 설계는 요한 지시로 정했다(GPT 검토 없음).
  - 정해진 답: 인건비 비율 · 월세·공과금 · 가장 많이 쓴 항목(아직 안 정한 돈 빼고 큰 순서 3개) · 아직 안 정한 돈은 질문 낱말로 알아보고 AI 없이 요약에서 바로 만든다
    (AI 호출·사용량 예약 0, 응답 `source:'fixed'`). 항목이 없으면 「이번 요약에는 …로 정한 거래가 없습니다」 + 아직 안 정한 돈.
  - 「왜 남는 게 적나요」(124-6, 운영판단 중 「왜 남」「남는 게 적」): 선택한 달과 바로 앞 달(요약의 가장 늦은 이전 달)로 전제(번 돈 늘고 차액 줄었는지)를 먼저 확인한다.
    맞으면 「○월 사업으로 번 돈은 ○월보다 늘었고, 차액은 줄었습니다」, 다르면 「질문과 달리 …」로 실제 움직임. 두 달의 번 돈·쓴 돈·차액을 나란히, 앞 달보다 많이 늘어난 지출 항목 둘을 두 달 금액과 함께.
    원인은 단정하지 않는다(「때문에」 없음). 아직 안 정한 돈이 쓴 돈의 10% 이상이면 그 금액을 적고 항목으로 세지 않는다. 중간 달이면 기준일 안내를 먼저.
    백테스트 2차에서 이 질문의 AI 답 11개 중 9개가 숫자 검사에 걸려 대체 답이 됐다.
  - 그 밖의 질문은 AI 답을 받은 뒤 검사한다(`checkAnswer`): 금액(억·만 단위 포함)·비율(% 소수 첫째 자리 반올림)·단독 소수·「YYYY년 M월」·「M월」(요약의 달만)·
    「M월 D일」·「D일까지」(마지막 거래일만)가 요약에 있는지, 아직 안 정한 돈을 「가장 큰 항목」으로 말하지 않는지.
  - **달-숫자 짝(124-6)**: 문장 안에서 「이번 달」「지난달」(달력상 바로 앞 달)「○월」 뒤에 쓴 번 돈·쓴 돈·차액이 그 달 그 칸의 값인지 본다.
    「6월보다」「지난달과 비교」처럼 비교 기준으로 쓴 달은 기준 달로 기억하고, 「A원에서 B원으로」의 A 는 기준 달·B 는 선택한 달 값이어야 한다.
    「76,953,445원 사업으로 번 돈」처럼 금액 뒤 칸 낱말, 「6월:」처럼 달 이름만 있는 줄 아래 목록도 읽는다. 항목 이름·아직 안 정한 돈·매출이 나오면 칸 기억을 지운다.
    백테스트 2차 #3·#5(「지난달」이라며 5월 숫자)가 숫자 자체는 요약에 있어 앞의 검사를 통과했기 때문이다.
  - **AI 에는 선택한 달과 바로 앞 달 하나만**(124-6): 앱은 지금처럼 이전 달 최대 3개를 보내고, 서버가 가장 늦은 달 하나만 남겨 AI 에 보낸다. 숫자 검사·대체 답도 그 요약으로 한다.
  - 검사에 걸리면 그 답을 버리고 대체 답(`fallbackAnswer`: 보고 계신 달과 바로 앞 달의 번 돈·쓴 돈·차액, 중간 달이면 기준일 안내 + 「자세한 설명을 만들지 못해 확인된 숫자만 보여 드립니다.」)을 보낸다(`source:'fallback'`).
  - 운영자 확인을 켠 질문도 **최종 답만** 저장한다. 버린 AI 답 원문은 어디에도 남기지 않는다.
  - 오프라인 평가(2026-10-16, 1·2차 백테스트 답 110개 + 규칙 위반 예시): 틀린 답 7개(값 9개) 모두 잡음, 규칙 위반 16개 모두 잡음, 맞는 답을 버린 것 0/87.
- **답변 지침(SYSTEM)**: 운영판단은 평가 대신 확인 가능한 지난달 대비 변화만(「왜」 질문은 단정하지 않고 번 돈·쓴 돈·차액과 가장 큰 항목들을 나란히), 잔액차이는 일반 설명, 업종비교는 「남는돈에는 같은 업종 비교 자료가 아직 없어 비교해 드릴 수 없습니다」 + 대신 볼 것 한 가지,
  앞으로지출은 정할 수 없다고 말하고 보고 계신 달 숫자만, 자료범위는 전체 기간 확보 여부를 먼저 말한다. 요약에 숫자를 새로 더하지 않았다.
- 「보낼 내용 보기」는 실제로 보낼 요약 객체 하나를 한글 표로 보여준다. 값을 다시 계산하지 않고 글자로만 바꾼다.
  - 순서: 업종 → 선택한 달·전체 자료의 마지막 거래일·전체 기간 확보 여부 → 사업으로 번 돈·사업에 쓴 돈·차액 →
    매출·그 밖의 입금·아직 안 정한 돈 → 항목별 금액·매출 대비 비율, 업종별 재료·매입 비율 → 이전 달 요약(달 이름으로 접음).
  - 금액은 원 단위 쉼표, 비율은 소수 첫째 자리 %. 계산 못 한 비율(null)은 「확인 보류」. 표 아래 「비율은 보기 쉽게 반올림했습니다」.
  - 요약에 시작일은 없다. `dataEnd`는 「전체 자료의 마지막 거래일」로 쓴다(「8월 1~22일」로 만들지 않는다).
    `complete=false`는 「전체 기간 확보 미확인」이다(「진행 중」이 아니다).
- 보내기에서만 질문과 허용된 월 요약을 전송한다. 대화 이력은 전송하지 않는 단문 질문 단계다 — 말풍선이 이어져도 서버는 앞 질문을 모른다(ⓘ 안의 「앞선 대화는 답변에 반영되지 않습니다.」).
- 원본 파일·거래 행·거래처 이름·매장 이름·계좌 정보·적요는 요약에 넣지 않는다.
- 사용자 지정 항목명에도 개인 이름이 있을 수 있어 `사용자 지정 항목`으로 합친다. 서버도 고정 항목명만 받는다.
- 비교는 직전 완결 달 최대 3개다. 거래일 범위가 모든 계좌에서 해당 월 첫날~말일을 포함해야 완결로 본다.
  거래가 없는 날과 파일 누락을 구분하지 못할 때는 미완결로 두는 보수적 기준이다. 연간 화면에서도 선택된 **달**을 명시한다.
- 질문 창을 열 때 요약을 고정하며 펼쳐 보는 값과 전송값이 같다. 매장·달 변경 시 다시 열도록 한다.
- `share=false`는 **운영자 열람용 대화·요약을 저장하지 않는다**는 뜻이다. 식별자 없는 일별 사용량은 계속 기록한다.
- 운영자 확인용 저장을 켠 질문만 질문·답변·업종·작성 시각·대화 번호와 삭제 키 해시를 D1에 저장한다. 답변에 들어간 금액도 저장된다.
- 예약 작업이 **1시간마다**(`15 * * * *`) 운영자 확인용 원문 **14일** 경과분과 주제 집계 **90일** 경과분을 지운다. 관리 목록에서는 이미 14일 지난 대화를 숨긴다.
  물리 삭제에는 예약 주기만큼 최대 1시간 지연이 있을 수 있다. 보관 전체는 아래 「보관 기간」.
- `fc.ai.enabled`(표시 끄기 — `'0'` 이면 꺼짐, 없으면 켜짐), `fc.ai.usage`(UTC 일자·횟수), `fc.ai.receipt`(대화 번호·삭제용 비밀 키)를 쓴다.
  `fc.ai.tester`(시험 기간의 시험자 키)는 124-5 부터 쓰지 않고, 남아 있으면 지운다.
  기존 매장 저장 형식은 바꾸지 않는다. 대화 본문·요약·운영자 확인 켬 상태는 브라우저 저장소에 저장하지 않는다.
- 대화 번호만 알아서는 삭제할 수 없다. 브라우저의 256비트 삭제 키를 Authorization으로 보내고 서버에서는 해시로 대조한다.
  삭제는 해당 브라우저의 키에 연결된, 운영자 확인용으로 저장된 대화 전체다. 다른 기기 대화는 지우지 않는다.
  저장소를 지우면 키도 사라진다.
  - ⋯ 메뉴의 「대화 삭제」 아래 설명은 한 문장이다: 「운영자 확인용으로 서버에 저장된 이 브라우저의 대화를 지웁니다.」
  - 화면에서 뺀 설명(여기에 남긴다): 매장 「지우기」는 이 브라우저의 매장 자료만 지우고 서버 대화는 지우지 않는다.
    브라우저 저장소(사이트 데이터)를 지우면 지우기 키(`fc.ai.receipt`)도 사라져 그 뒤로는 이 브라우저에서 서버 대화를 지울 수 없다 — 14일 예약 삭제를 기다리거나 운영자가 관리 화면에서 지운다.

## 사용량과 오류

- 모델: `@cf/mistralai/mistral-small-3.1-24b-instruct`(2026-10-16 합성 자료 측정으로 선택, `chat/wrangler.jsonc` `CHAT_MODEL`). 목록 밖 모델 이름이면 503이다.
  `compatibility_date`는 `2026-09-30`(wrangler 4.139.0 이 지원하는 마지막 날짜. 그보다 뒤면 로컬 실행이 멈춘다).
- 일별 한도 기본 8,000뉴런. D1 원자적 SQL로 호출 전 입력 바이트 수와 최대 출력량에 해당하는 양을 예약한다.
  모델 사용량 응답이 있으면 공식 단가로 정산하며, 사용량이 없거나 실패하면 예약량을 남긴다.
- 입력 바이트 기반 예약은 보수적 추정이다. 선택한 모델의 실제 토큰 수가 예약 상한을 넘지 않는지 실측해야 한다.
- UTC 자정(한국시간 오전 9시)에 일자가 바뀐다. 브라우저별 10회는 보조 장치이며 실패 요청도 횟수에 포함한다.
- CORS는 앱 origin 하나만 허용한다. CORS 자체는 인증이나 남용 방지가 아니다.
  공개 API를 직접 호출하면 하루 한도를 다 쓸 수 있다. 124-5 공개에서는 Cloudflare 요청 수 규칙(검증방 설정)에 맡겼다 — 코드 안 IP 별 제한은 없다.
- 서버 장애·한도 초과가 앱 계산이나 저장을 바꾸지 않는다. AI 출력은 HTML로 실행하지 않고 글자로만 표시한다.
- 지시문(`SYSTEM`)은 차액을 「선택한 기간의 사업으로 번 돈 − 사업에 쓴 돈」으로 설명하고, 통장 잔액은 그 기간 전 잔액·대표님이 넣거나 가져간 돈·대출 등으로 다를 수 있다고 말하게 한다.
  계좌 간 이체 영향은 함께 보는 계좌에 따라 다르고 미정 거래도 차액에 영향을 준다. 요약에 시작·끝 잔액과 전체 입출금이 없으므로
  차이의 정확한 원인·금액은 확인할 수 없다고 말하며, 미분류 금액을 입출금으로 나누거나 날짜를 추정하지 않는다. 요약에 잔액은 넣지 않는다(잔액 칸이 있으면 400).
- 숫자 말하기(SYSTEM): 두 달을 비교할 때 차이를 직접 계산하지 않고 두 달 숫자를 나란히 말한다. 이번 달이 중간 자료면 「이번 달은 ○일까지의 자료라 지난달 한 달 전체와 바로 비교하기 어렵습니다」를 먼저 말한다.
  비율은 % 소수 첫째 자리, 금액은 쉼표와 「원」. 1차 측정에서 차이 계산 6개가 틀려 넣었다. 2차 측정에서 차이 계산 0, 다만 비율 두 자리·업종비교의 안내 문장 빠짐이 남았다.

2. 서버 `chat/src/index.js`: `testerAllowed`·`TESTER_FORM` 제거, CORS 허용 헤더에서 시험자 헤더 제거, `/api/topic` 기본 꺼짐(`TOPIC_COUNTS`), 정해진 답·숫자 검사·대체 답(`answers.js`).
3. **남은 것**: Cloudflare 에 넣은 `TESTER_KEY` 비밀값은 이제 쓰지 않는다 — 요한이 `wrangler secret delete TESTER_KEY --config chat/wrangler.jsonc` 로 지운다.
4. 처리방침(사이트)과 앱 안내의 처리 위치·보관 기간은 같은 날 맞춘다. 주제 집계를 다시 켜려면 처리방침부터 고친다.

## Cloudflare에서 사람이 할 일 — 여기서는 실행하지 않음

1. 지원이 코드를 검토하고 운영자가 외부 시험 범위를 승인한다. 합성 자료부터 시험한다.
2. (2026-10-16 완료) D1 생성: `wrangler d1 create namneundon-chat --jurisdiction=us`(jurisdiction us, 지역 미국 서부). ID를 `chat/wrangler.jsonc`에 넣고
   `chat/migrations/0001_init.sql`, `0002_topics_notes.sql`을 차례로 적용한다(기존 파일은 고치지 않고 새 파일로만 더한다).
   (시험 기간에 넣은 `TESTER_KEY` 비밀값은 124-5 부터 쓰지 않는다 — 위 「공개 전환」 3번.)
3. (2026-10-16 완료) 모델 실측 후 `CHAT_MODEL` 을 mistral-small-3.1-24b 로 넣었다. 지시 무시 요청 시험은 아직이다.
4. `chat.namneundon.com`을 별도 Worker custom domain으로 연결한다. workers.dev·미리보기 주소는 계속 비활성화한다.
5. Cloudflare Access 앱을 `/admin` 및 `/api/admin/*`에 적용하고 운영자 이메일 하나만 허용한다.
   `ACCESS_TEAM`에는 팀 하위 도메인만(예: `bitter-rice-6e3b` — 코드가 `https://<팀>.cloudflareaccess.com`을 만든다), `ACCESS_AUD`에는 해당 Access 앱 AUD를 넣는다. (2026-10-16 값 넣고 다시 배포)
   서버는 헤더 존재뿐 아니라 RSA 서명·발급자·대상·유효기간을 검증한다. 다른 주소로 우회되지 않는지도 시험한다.
6. 무료 플랜과 계정 전체의 다른 AI 사용량을 확인한다. 자동 유료 전환·AI Gateway 크레딧은 연결하지 않는다.
7. 입력·출력·오류 로그에 본문이 남지 않는지, 실제 모델 사용량과 D1 정산이 일치하는지 확인한다.
8. 예약 삭제·사용자 삭제·삭제 실패 재시도, 관리 화면 인증·만료·위조 토큰 거절을 실제 환경에서 확인한다.
9. 실제 처리업체·국가·보관·국외 이전 근거를 확인하고 개인정보 안내·그림을 웹사이트방과 맞춘다.
   기존 “거래내역이 밖으로 나가지 않음” 문구의 적용 범위와 AI 예외를 공개 전에 반영한다.
10. 서버 오류 시 기존 분석 유지, 360·390폭, 질문 전에는 무전송, 운영자 확인 꺼진 질문에 지우기 키·convId 없음을 외부 시험 환경에서 다시 확인한다.
11. 배포 작업은 `CHAT_DEPLOY_ENABLED=true`를 사람이 설정한 뒤 `workflow_dispatch`일 때만 열린다.
    D1·모델·Access 자리표시가 남으면 건너뛴다. **같은 workflow의 기존 앱 배포도 실행되므로** 실행 전 대상을 확인한다.
    D1 마이그레이션은 자동 실행하지 않는다. 운영자 배포 승인 전 이 설정을 켜지 않는다.
12. 배포 뒤 할 일: `wrangler tail`로 합성 질문·가짜 키 요청을 보내 tail 출력에 URL·헤더(Authorization)·IP가 어떻게 나오는지 실측한다.
    D1 되돌리기(Time Travel)로 되살린 뒤에는 그 사이 지운 대화가 다시 생기므로 지운 대화를 다시 지우는 절차를 정해 둔다.
